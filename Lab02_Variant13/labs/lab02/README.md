# Лабораторна робота 2

Лозинский Р.Р., КБ-202. Варіант 13 — Сканер витоків конфіденційних даних.

## Підготовка

Python 3.10 або новіший. Робочий код використовує лише стандартну бібліотеку;
Ruff потрібен для контролю якості. Команди виконуються з кореня проєкту.

```sh
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Для Windows активація: `.venv\Scripts\activate`.
Якщо вже є репозиторій ЛР1, перенесіть у нього `labs/lab02/` і `tests/test_lab02.py`,
у наявному `shared/student.py` установіть `VARIANT_NUMBER = 13`,
а до наявного `requirements.txt` додайте Ruff, зберігши залежності ЛР1.

## Структура

```text
shared/student.py
labs/lab02/main.py       # підкоманди demo та analyze
labs/lab02/task1.py      # користувач, адміністратор, сеанс, аудит
labs/lab02/task2.py      # пошук PII, маскування, JSON
labs/lab02/data/data_v13/scan/
    clean.txt
    exports/export.json
    logs/app.log
    notes/users.txt
tests/test_lab02.py
results/                # результати фактичних запусків
```

Дані навчальні. Аналізуються всі звичайні UTF-8 текстові файли рекурсивно,
зокрема `.txt`, `.log`, `.json`; символічні посилання не відкриваються.
Недоступні файли, двійкові файли та невалідний UTF-8 пропускаються з WARNING.
Помилка обходу каталогу завершує аналіз, щоб не видавати неповний результат за повний.

## Запуск

```sh
python -m labs.lab02.main demo
python -m labs.lab02.main analyze --scan-dir labs/lab02/data/data_v13/scan --patterns all --mask --out-json results/pii_all.json
python -m labs.lab02.main analyze --scan-dir labs/lab02/data/data_v13/scan --patterns cards --mask --out-json results/pii_cards.json
python -m labs.lab02.main analyze --scan-dir labs/lab02/data/data_v13/scan --patterns emails --mask --out-json results/pii_emails.json
```

`--scan-dir` і `--out-json` обов'язкові; `--patterns` приймає `all` (типово),
`cards` або `emails`; `--mask` — булевий прапорець без значення.
За `all` також шукаються телефони та IPv4.
Маскування застосовується і до консолі, і до поля value в JSON, оригінал не додається.
Без `--mask` консоль і JSON містять вихідні значення навчальних даних.
Logging передає INFO/WARNING/ERROR у stderr без значень PII.
Код завершення 0 означає завершення сканування (навіть якщо знайдено PII),
1 — помилку каталогу чи запису, 2 — некоректні аргументи argparse.

Вихідний звіт розміщуйте поза каталогом сканування, як у прикладах.
Вже наявний файл звіту поза каталогом сканування перезаписується.
Збереження всередині вхідного каталогу відхиляється, щоб не перезаписати дані.

## Алгоритм та обмеження

os.walk із pathlib.Path обходить вкладені каталоги. Кожен файл читається окремо; рядки
перевіряються регулярними виразами, Counter підраховує кожне входження.
JSON містить час UTC, кількість файлів і пропусків, counts та findings
(відносний шлях, рядок, стовпець з 1, тип, значення).
Результат стабільно впорядкований за шляхами, потім рядками та типами.

Email сканера допускає крапки й знаки + у локальній частині; в User.email
застосовано інший, суворіший формат з умови завдання 1 (латинська літера,
потім 2–63 латинські літери, цифри або _, домен із крапкою).
IPv4 додатково перевіряється через ipaddress.IPv4Address.
Картки: 16 цифр разом або 4 групи по 4 цифри через пробіл/дефіс.
Це пошук кандидатів, без перевірки Luhn чи підтвердження чинності картки.
Телефони: міжнародний формат із + та 10–15 цифрами або локальний
формат 0XXXXXXXXX. Підрядки карток не рахуються телефонами.
IPv6, OCR, офісні архіви та всі можливі світові формати телефонів не охоплено.
Вихідні файли не редагуються; --mask маскує копії знайдених значень.

## Очікуваний результат на наданих даних

4 файли, 15 входжень: email 4, картки 3, телефони 4, IPv4 4.
clean.txt не містить збігів. export.json містить 5, app.log — 5,
users.txt — 5. Знахідки означають відкриті PII в тексті, але самі по собі
не доводять передачу даних сторонній особі.

## Додавання до наявного репозиторію ЛР1

Після перенесення й перевірки всього репозиторію:


Ці команди наведені для виконання у вашому репозиторії. Архів не містить `.git`
та не створює нового репозиторію. URL репозиторію й коміт у звіті заповнюються
після фактичної публікації.
